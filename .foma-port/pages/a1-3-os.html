Операционные и управляющие системыOperating systems and control systems

Тема A1.3 — про два типа «дирижёров» в мире вычислений. Операционная система (OS) управляет ресурсами компьютера: процессорным временем, памятью, дисками, сетью, безопасностью. Управляющая система (control system) регулирует поведение физического устройства — лифта, термостата, машины — через датчики, контроллер, актуаторы и обратную связь. Operating system (OS) manages the computer's resources: processor time, memory, disks, the network and security. Control system regulates the behaviour of a physical device (an elevator, a thermostat, a car) through sensors, a controller, actuators and feedback. Both work on the same idea: hide complexity and make decisions based on data. Sections A1.3.5 – A1.3.7 are HL only.

1. A1.3.1 Роль операционной системы1. A1.3.1 Role of the operating system

Операционная система (OS) — это посредник (interface) между пользователем, приложениями и аппаратным обеспечением (hardware). Её задача — управлять системными ресурсами (CPU, память, диск, сеть, периферия) и предоставлять сервисы приложениям и пользователю: файловую систему, управление процессами, безопасность, графический интерфейс. Operating system (OS) is an intermediary between the user, applications and hardware. Its job is to manage system resources (CPU, memory, disk, network, peripherals) and to provide services to applications and the user: the file system, process management, security and the graphical interface.

Примеры ОС: Linux, Windows, macOS, Android, iOS, BSD, Orbis (для PlayStation). У каждой свои сильные стороны — нет «лучшей» ОС, есть только наиболее подходящая под конкретную задачу. Examples of operating systems: Linux, Windows, macOS, Android, iOS, BSD, Orbis (for PlayStation). Each has its own strengths. There is no “best” OS, only the most suitable one for a particular task.

🎭 Абстракция железа (hardware abstraction)🎭 Hardware abstraction

Абстракция (abstraction) — это сокрытие сложных деталей за простым интерфейсом. Когда ты играешь в видеоигру, ты не думаешь о том, как распределяются потоки, как выделяется память, как драйверы общаются с GPU. Ты просто играешь. Это и есть работа ОС — спрятать всю сложность. Abstraction is hiding complex details behind a simple interface. When you play a video game, you do not think about how threads are scheduled, how memory is allocated or how drivers talk to the GPU. You just play. This is exactly the job of the OS: to hide all that complexity.

Аналогия из жизни: руль и педали в машине. Тебе не нужно понимать, как работает двигатель внутреннего сгорания, чтобы ехать. Руль, педали и коробка передач — это интерфейс к сложной механике. A real-life analogy: the steering wheel and pedals in a car. You do not need to understand how an internal combustion engine works in order to drive. The steering wheel, pedals and gearbox are an interface to complex machinery.

💡 Если бы каждое приложение само управляло памятью, диском и CPU, был бы хаос (chaos): программы конфликтовали бы за ресурсы, ломали друг друга, нарушали безопасность. ОС играет роль дирижёра оркестра — каждый «инструмент» (приложение) играет свою партию в нужный момент. 💡 If every application managed memory, the disk and the CPU itself, there would be chaos: programs would fight over resources, break each other and undermine security. The OS plays the role of an orchestra conductor: each “instrument” (application) plays its part at the right moment.
🇬🇧 English summary (click to expand)

An operating system sits between the user and the hardware, sharing out the CPU, memory, storage and peripherals while offering services such as a file system, process management, security and a user interface. Common examples include Linux, Windows, macOS, Android and iOS — none is universally best; each suits different jobs. Its central trick is hardware abstraction: applications never poke registers or drivers directly, they make system calls and the OS handles the messy details. That lets the same program run on very different machines and stops one app from corrupting another.

2.1 Что такое процесс (process)?2.1 What is a process?

⚙️ Процесс — это выполняющаяся программа⚙️ A process is a running program

Программа (program) — пассивный набор инструкций на диске. Процесс (process) — активное выполнение этих инструкций в памяти. Когда ты дважды кликаешь иконку, ОС создаёт процесс для управления выполнением программы. Из одной программы можно запустить несколько процессов. Program — a passive set of instructions on disk. Process — the active execution of these instructions in memory. When you double-click an icon, the OS creates a process to manage the running of the program. You can start several processes from one program.

2.2 Поток (thread)2.2 Thread

Поток (thread) — это самая маленькая единица выполнения, которой управляет планировщик. Внутри одного процесса может быть много потоков, и они делят память. Пример: текстовый редактор может иметь поток для отрисовки документа, поток для проверки орфографии в фоне и поток для обработки ввода с клавиатуры — всё одновременно. Thread — the smallest unit of execution that the scheduler manages. A process can contain many threads, and they share memory. Example: a word processor may have one thread for drawing the document, one for checking spelling in the background and one for handling keyboard input — all at the same time.

2.4 Управление памятью (memory management)2.4 Memory management

ОС выделяет и освобождает память процессам, защищает адресные пространства друг от друга, и реализует виртуальную память (virtual memory). Виртуальная память позволяет процессам «думать», что у них больше памяти, чем есть физически — за счёт пейджинга (paging): лишние страницы памяти временно перекладываются на диск (swap space). The OS allocates and frees memory for processes, protects their address spaces from one another, and implements virtual memory. Virtual memory lets processes “believe” that they have more memory than is physically available, through paging: surplus pages of memory are temporarily moved to disk (swap space).

Page (страница) — это фиксированный непрерывный блок виртуальной памяти. Без виртуальной памяти такие блоки называются page frames. MMU (Memory Management Unit) в железе помогает ОС динамически отображать виртуальные адреса на физические. Page — a fixed, contiguous block of virtual memory. Without virtual memory such blocks are called page frames. The MMU (Memory Management Unit) in the hardware helps the OS map virtual addresses to physical addresses dynamically.

2.5 Файловая система (file system)2.5 File system

Метод, которым ОС хранит и читает данные. Организует данные блоками на диске, определяет правила именования файлов, структуру каталогов, права доступа. Примеры: NTFS (Windows), ext4 (Linux), APFS (macOS). The method by which the OS stores and reads data. It organises data in blocks on the disk and defines rules for naming files, the directory structure and access rights. Examples: NTFS (Windows), ext4 (Linux), APFS (macOS).

2.6 Управление устройствами (device management)2.6 Device management

ОС общается с аппаратурой через драйверы (drivers). Драйвер переводит команды ОС в специфические для устройства сигналы. Когда ты двигаешь мышь, она генерирует прерывание — драйвер передаёт его в ОС, та обновляет позицию курсора. Драйверы также дают единый интерфейс приложениям: они не должны знать, какая конкретно мышь подключена. The OS communicates with hardware through drivers. A driver translates OS commands into signals specific to the device. When you move the mouse, it generates an interrupt: the driver passes it to the OS, which updates the position of the cursor. Drivers also give applications a single common interface: they do not need to know which particular mouse is connected.

2.7 Планирование (scheduling)2.7 Scheduling

Решение, кто и когда получает время CPU. Учитывает приоритет, справедливость, эффективность, нагрузку. Подробно — в разделе A1.3.3. The decision about which process gets CPU time, and when. It takes into account priority, fairness, efficiency and load. For details, see section A1.3.3.

2.8 Безопасность (security)2.8 Security

ОС предоставляет firewall, шифрование, контроль доступа, аутентификацию пользователя, патчи безопасности, sandboxing, логирование, проверки целостности данных. The OS provides a firewall, encryption, access control, user authentication, security patches, sandboxing, logging and data integrity checks.

2.9 Учёт ресурсов (accounting)2.9 Resource accounting

ОС отслеживает использование ресурсов: сколько CPU-времени, памяти, диска, сетевого трафика «съел» каждый процесс. Раньше это нужно было, чтобы выставлять счета пользователям мейнфреймов. Сегодня — снова актуально для облачных вычислений (cloud computing), где платишь «за использование». The OS tracks resource use: how much CPU time, memory, disk and network traffic each process has “consumed”. Originally this was needed to bill users of mainframes. Today it matters again for cloud computing, where you pay “for use”.

2.10 Графический интерфейс (GUI)2.10 Graphical user interface (GUI)

Windows, macOS и большинство Linux-сред имеют разные GUI, но их роль одна: визуальный интерфейс с иконками, окнами, меню, кнопками. Хороший GUI упрощает использование; плохой GUI мешает работе. Эта тема — часть human–computer interaction (HCI). Windows, macOS and most Linux desktop environments have different GUIs, but their role is the same: a visual interface with icons, windows, menus and buttons. A good GUI makes things easier to use; a poor GUI gets in the way of work. This topic is part of human–computer interaction (HCI).

2.11 Виртуализация (virtualization)2.11 Virtualisation

🏢 Один физический сервер, много виртуальных машин🏢 One physical server, many virtual machines

Виртуализация — создание виртуальных копий физического железа. Один компьютер может «хостить» несколько виртуальных машин (VM), и каждая работает так, будто у неё своё собственное железо. Аналогия: один большой дом разделили на отдельные квартиры — каждая со своими «комнатами» (ресурсами), но в одном здании. Virtualisation is creating virtual copies of physical hardware. One computer can “host” several virtual machines (VMs), and each one works as if it had its own hardware. An analogy: one large building is divided into separate flats, each with its own “rooms” (resources), but all in the same building.

Ключевая технология — гипервизор (hypervisor): программный слой между виртуальными машинами и физическим железом. Гипервизор распределяет ресурсы между VM и изолирует их друг от друга. The key technology is the hypervisor: a software layer between the virtual machines and the physical hardware. The hypervisor allocates resources between the VMs and isolates them from one another.

Два главных преимущества:Two main advantages:

  • Эффективное использование железа — несколько VM делят один CPU/память/диск, повышая загрузку.Efficient use of hardware — several VMs share one CPU, memory and disk, which raises utilization.
  • Изоляция — сбой или взлом одной VM не влияет на другие.Isolation — a fault or breach in one VM does not affect the others.

2.12 Сетевые функции (networking)2.12 Networking functions

ОС реализует сетевой стек (network stack) — слои TCP/IP. Управляет сетевыми картами через драйверы, настраивает IP-адреса (статически или через DHCP), применяет шифрование (SSL/TLS), фильтрует пакеты файрволом. В комплекте идут утилиты: ping, ifconfig/ipconfig, netstat, traceroute/tracert. The OS implements the network stack — the TCP/IP layers. It manages network cards through drivers, configures IP addresses (statically or through DHCP), applies encryption (SSL/TLS) and filters packets through a firewall. Built-in utilities include: ping, ifconfig/ipconfig, netstat, traceroute/tracert.

🇬🇧 English summary (click to expand)

A modern OS juggles many duties at once. It schedules CPU time across processes and threads, allocates and protects memory (often with paging and virtual memory via the MMU), manages a file system on disk, drives peripherals through device drivers, and runs the network stack. It also enforces security through user/kernel separation, sandboxing, access control lists, encryption, firewalls and patching. A process is a running program with its own memory and PID, cycling through new, ready, running, blocked and terminated states; threads share a process's memory. Virtualisation, accounting and the GUI round out the picture.

3. A1.3.3 Подходы к планированию3. A1.3.3 Scheduling approaches

Планирование (scheduling) — это решение, в каком порядке и сколько времени каждому процессу даётся на CPU. ОС оценивает эффективность планировщика через throughput (сколько процессов завершено за единицу времени), turnaround time (сколько прошло от поступления до завершения), waiting time и CPU utilization. Scheduling — the decision about the order in which, and for how long, each process gets the CPU. The OS evaluates the efficiency of the scheduler using throughput (how many processes finish per unit of time), turnaround time (the time from arrival to completion), waiting time and CPU utilization.

3.1 Ключевые термины3.1 Key terms

Slice (квант времени, срез) — сколько CPU-времени даётся процессу, прежде чем его прервут или заменят.Time slice — how much CPU time a process is given before it is interrupted or replaced.
Quantum — фиксированный квант времени в pre-emptive системах (например, round robin).Quantum — a fixed time slice in pre-emptive systems (for example, round robin).
Pre-emption (вытеснение) — способность планировщика прервать выполняющийся процесс и отдать CPU более приоритетному.Pre-emption — the ability of the scheduler to interrupt the running process and give the CPU to a higher-priority one.
Fairness (справедливость) — равноправное распределение CPU между всеми процессами.Fairness — an equal sharing of the CPU among all processes.
Starvation (голодание) — процесс никогда не получает CPU, потому что другие постоянно мешают.Starvation — a process never gets the CPU because others keep getting in the way.
Efficiency (эффективность) — максимум throughput, минимум waiting time.Efficiency — maximum throughput, minimum waiting time.
Context switching (переключение контекста) — сохранение состояния одного процесса и загрузка другого; занимает время и снижает производительность.Context switching — saving the state of one process and loading another; it takes time and reduces performance.

3.2 Четыре алгоритма планирования3.2 Four scheduling algorithms

🚶 FCFS — First-Come, First-Served

Процессы получают CPU в том порядке, в котором пришли. CPU обслуживает один процесс до конца, потом следующий. Не вытесняющий (non-pre-emptive): начатый процесс работает до завершения. Processes get the CPU in the order in which they arrived. The CPU serves one process to completion, then the next. Non-pre-emptive: a process that has started runs until it finishes.

Аналогия: очередь в кассе — кто раньше подошёл, тот раньше обслужен.Analogy: a checkout queue — whoever arrives first is served first.

Где использовать: простые среды с предсказуемой длиной задач, когда важна простота и предсказуемость, а не максимальная пропускная способность.Where it is used: simple environments with predictable job lengths, where simplicity and predictability matter more than maximum throughput.

🔁 Round Robin

Вытесняющий (pre-emptive) алгоритм. Каждому процессу даётся фиксированный квант времени (time quantum). Если процесс не завершился — его отправляют в конец очереди, следующий получает CPU. Круг повторяется — отсюда «round robin». Pre-emptive algorithm. Each process is given a fixed time quantum. If the process has not finished, it is sent to the back of the queue and the next process gets the CPU. The cycle repeats — hence “round robin”.

Аналогия: учитель опрашивает учеников по очереди, каждому даёт 30 секунд.Analogy: a teacher questions students in turn, giving each one 30 seconds.

Тонкость: размер кванта критичен. Слишком короткий — много переключений контекста (большие накладные расходы). Слишком длинный — алгоритм вырождается в FCFS.Subtlety: the size of the quantum is critical. If it is too short, there are many context switches (a large overhead). If it is too long, the algorithm degenerates into FCFS.

Где использовать: системы с разделением времени (time-sharing), многозадачные системы, где важна отзывчивость для всех пользователей.Where it is used: time-sharing systems and multitasking systems where responsiveness for all users matters.

📚 Multilevel Queue Scheduling

Очередь готовых процессов разделена на несколько очередей, каждая со своим алгоритмом и приоритетом. Процессы навсегда закрепляются за одной очередью по своему типу (например, системные vs пользовательские, фоновые vs интерактивные). The ready queue is divided into several queues, each with its own algorithm and priority. Processes are permanently assigned to one queue according to their type (for example, system vs user processes, background vs interactive).

Между очередями планирование может быть фиксированно-приоритетным (высокая очередь всегда первая) или по round robin между очередями. Between the queues, scheduling can be fixed-priority (the higher queue always goes first) or round robin between the queues.

Аналогия: в больнице — три очереди: критические пациенты, срочные, плановые. Критических обслуживают первыми, но плановые тоже не забывают.Analogy: in a hospital there are three queues: critical patients, urgent cases and routine appointments. Critical patients are seen first, but routine cases are not forgotten either.

Где использовать: сложные системы со смешанными типами процессов — например, ОС, которая балансирует системные и пользовательские задачи.Where it is used: complex systems with mixed types of process — for example, an OS that balances system and user tasks.

⭐ Priority Scheduling

У каждого процесса есть приоритет, и CPU получает тот, у кого приоритет выше. Бывает вытесняющим (pre-emptive) — пришёл более важный, вытеснил текущий — и невытесняющим (non-pre-emptive) — текущий доработает, потом проверим очередь. Each process has a priority, and the CPU goes to the one with the higher priority. It can be pre-emptive — a more important process arrives and displaces the current one — or non-pre-emptive — the current process finishes first, and then the queue is checked.

Аналогия: в аэропорту — пассажиров с золотой картой пускают вперёд, остальные ждут.Analogy: at an airport, passengers with a gold card are let through first while the others wait.

Минус: риск starvation — низкоприоритетный процесс может «никогда» не получить CPU. Решение — ageing (постепенно повышать приоритет ожидающих).Drawback: a risk of starvation — a low-priority process may “never” get the CPU. The solution is ageing (gradually raising the priority of waiting processes).

Где использовать: системы реального времени (real-time), где критично выполнить высокоприоритетные задачи вовремя — медицинская техника, автоматика, авиатехника.Where it is used: real-time systems, where it is critical to complete high-priority tasks on time — medical equipment, automation, aviation systems.

4. A1.3.4 Polling vs Interrupts

Два способа, которыми CPU узнаёт, что внешнее устройство или программа требует внимания. Two ways in which the CPU finds out that an external device or program needs attention.

🔔 Interrupt (прерывание)🔔 Interrupt

Устройство само посылает сигнал процессору: «эй, у меня данные, обработай!». CPU прерывает текущую работу, сохраняет контекст и запускает Interrupt Service Routine (ISR) — специальную процедуру для этого события. После ISR процессор возвращается к прерванному делу. A device sends a signal itself to the processor: “hey, I have data, deal with it!”. The CPU interrupts the current work, saves the context and starts an Interrupt Service Routine (ISR) — a special procedure for this event. After the ISR, the processor returns to the interrupted task.

Аналогия: ты работаешь, и звонит дверной звонок. Ты прерываешься, идёшь открыть, потом возвращаешься к работе.Analogy: you are working when the doorbell rings. You stop, go to answer the door, then go back to your work.

🔄 Polling (опрос)🔄 Polling

Процессор сам периодически опрашивает устройства: «есть ли что-то новое?». Если нет — возвращается к работе и через какое-то время опросит снова. Если да — обрабатывает. The processor itself periodically polls the devices: “is there anything new?”. If not, it returns to its work and polls again after a while. If there is, it processes it.

Аналогия: ты ждёшь курьера, и каждые 5 минут идёшь к двери проверить, не пришёл ли он.Analogy: you are waiting for a courier, so every 5 minutes you walk to the door to check whether they have arrived.

5. A1.3.5 Многозадачность и распределение ресурсов HL5. A1.3.5 Multitasking and resource allocation HL

Многозадачность (multitasking) — способность ОС управлять и выполнять несколько процессов «одновременно». На самом деле в одно мгновение CPU выполняет один процесс, но переключается так быстро, что создаётся иллюзия параллельности. Этот механизм называется context switching (переключение контекста) — ОС сохраняет состояние текущего процесса (регистры, указатели памяти) и загружает состояние следующего. Multitasking — the ability of the OS to manage and run several processes “at the same time”. In reality, at any one moment the CPU runs only one process, but it switches so quickly that an illusion of simultaneous execution is created. This mechanism is called context switching — the OS saves the state of the current process (registers, memory pointers) and loads the state of the next one.

Распределение ресурсов (resource allocation) — эффективное раздавание CPU, памяти, диска, сети между процессами. Это сложная динамичная задача — миллионы решений в секунду. Resource allocation — the efficient distribution of the CPU, memory, disk and network among processes. It is a complex, dynamic task — millions of decisions per second.

🎛️ Как ОС жонглирует сотнями процессов🎛️ How the OS juggles hundreds of processes

  • Process management: ОС ведёт таблицу процессов (process table) с состоянием (running/waiting/blocked), приоритетом, использованием ресурсов.Process management: the OS keeps a process table with each process's state (running/waiting/blocked), priority and resource use.
  • Context switching: при переключении ОС сохраняет состояние в таблице и загружает следующий — обычно за микросекунды.Context switching: when switching, the OS saves the state in the table and loads the next one — usually in microseconds.
  • Многопоточность (multithreading): внутри процесса несколько потоков разделяют память и могут выполняться параллельно на multi-core CPU.Multithreading: inside a process, several threads share memory and can run in parallel on a multi-core CPU.

5.3 Вызовы планирования задач (task scheduling)5.3 Challenges of task scheduling

  • Fairness vs efficiency: справедливо раздать CPU всем — но высокоприоритетные не должны страдать, а низкоприоритетные не должны умирать.Fairness vs efficiency: the CPU should be shared fairly among everyone, but high-priority processes must not suffer and low-priority processes must not be starved.
  • Pre-emption: приостановка процесса в пользу более важного — даёт отзывчивость, но добавляет накладные расходы.Pre-emption: suspending a process in favour of a more important one — gives responsiveness, but adds overhead.
  • Starvation: в крайних случаях низкоприоритетные задачи никогда не получают CPU — нужны стратегии вроде ageing.Starvation: in extreme cases, low-priority tasks never get the CPU — strategies such as ageing are needed.

5.4 Resource contention (борьба за ресурсы)5.4 Resource contention

Происходит, когда несколько процессов хотят один и тот же ресурс, который не делится на всех. Это может привести к нескольким плохим состояниям: This happens when several processes want the same resource, which cannot be shared by all of them. It can lead to several problem states:

🔒 Deadlock (взаимная блокировка)🔒 Deadlock

Два или больше процессов ждут друг друга по кругу — никто не может продолжить. Классический пример: процесс A держит ресурс 1 и хочет ресурс 2; процесс B держит ресурс 2 и хочет ресурс 1. Оба зависнут навсегда. Two or more processes wait for each other in a circle — none of them can continue. A classic example: process A holds resource 1 and wants resource 2; process B holds resource 2 and wants resource 1. Both will hang forever.

Что делает ОС:What the OS does:

  • Detection (обнаружение): алгоритмы мониторят зависимости ресурсов и ловят циклы ожидания.Detection: algorithms monitor resource dependencies and detect circular waits.
  • Release the deadlock: ОС может завершить один из процессов, вытеснить его задачи, или перераспределить ресурсы.Release the deadlock: the OS can terminate one of the processes, pre-empt its tasks, or reallocate resources.
  • Prevention (предотвращение): deadlock avoidance algorithms (например, Banker's algorithm) проверяют, не создаст ли запрос на ресурс цикл — и отказывают, если да.Prevention: deadlock avoidance algorithms (for example, the Banker's algorithm) check whether a resource request would create a cycle — and refuse it if it would.

🔁 Livelock

Процессы постоянно запрашивают и отпускают ресурсы, но не продвигаются вперёд. В отличие от deadlock, они активны, но прогресса нет. Аналогия: два человека столкнулись в коридоре, оба отходят в одну сторону, опять блокируют друг друга, и так бесконечно. Processes keep requesting and releasing resources, but never move forward. Unlike deadlock, they are active, but there is no progress. Analogy: two people meet in a corridor, both step aside in the same direction, block each other again, and so on indefinitely.

💥 Thrashing

Возникает, когда страниц памяти не хватает, и ОС постоянно подкачивает (swap) страницы между RAM и диском. CPU тратит больше времени на пейджинг, чем на полезную работу. Решение — оптимизация demand paging и виртуальной памяти, добавление RAM. It happens when there is not enough memory, and the OS keeps swapping pages in and out between RAM and disk. The CPU spends more time on paging than on useful work. The solution is optimising demand paging and virtual memory, and adding RAM.

🇬🇧 English summary (click to expand)

Multitasking gives the illusion of simultaneous execution by switching contexts between processes very quickly; on multi-core machines, threads can also run in genuine parallel. The OS tracks every process in a process table and allocates memory through paging, segmentation and virtual memory. Sharing finite resources brings resource contention hazards: deadlock (processes block one another in a cycle), livelock (constant activity with no progress), and thrashing (excessive swapping between RAM and disk). Defences include deadlock detection, the Banker's algorithm for avoidance, ageing to prevent starvation, ordered resource requests, and quotas.

🧠 Controller (контроллер)🧠 Controller

Устройство или ПО, которое обрабатывает входы от датчиков и посылает сигналы актуаторам. Может быть встроенным микроконтроллером или промышленным PLC (Programmable Logic Controller). 🌡️ Sensors (датчики)🌡️ Sensors

Устройства, которые обнаруживают и измеряют физические величины (температура, свет, давление, движение, влажность) и превращают их в сигналы, понятные контроллеру. ⚙️ Actuators (актуаторы / исполнительные устройства)⚙️ Actuators

Механические или электронные устройства, которые совершают физическое действие в ответ на сигналы контроллера: моторы, клапаны, нагреватели, сирены. Mechanical or electronic devices that carry out a physical action in response to signals from the controller: motors, valves, heaters, sirens.

Пример: Solenoid valve (соленоидный клапан) в автоматической поливе — открывает/закрывает воду по команде контроллера, который читал данные с датчика влажности почвы.Example: a solenoid valve in an automatic watering system — opens and closes the water supply on command from the controller, which read data from the soil-moisture sensor.

🔄 Transducer (преобразователь)🔄 Transducer

Превращает одну форму энергии или сигнала в другую. Часто стоит между физическим миром и электроникой. Технически датчики и актуаторы — частный случай преобразователей. It converts one form of energy or signal into another. It often sits between the physical world and electronics. Technically, sensors and actuators are a special case of transducers.

Пример: Piezoelectric pressure sensor в системе мониторинга давления шин — преобразует давление в электрический сигнал, который читает бортовой компьютер; если давление вне нормы, водителю показывают предупреждение.Example: a piezoelectric pressure sensor in a tyre-pressure monitoring system — converts pressure into an electrical signal, which the on-board computer reads; if the pressure is outside the normal range, the driver is shown a warning.

📐 Control algorithm (алгоритм управления)📐 Control algorithm

Математическая формула или логика, которой контроллер пользуется, чтобы решить, какой выход дать на основе входа, цели и текущего состояния. A mathematical formula or logic that the controller uses to decide what output to produce, based on the input, the target and the current state.

Пример: PID-контроль (proportional–integral–derivative) в домашнем отоплении — мерит ошибку (разницу между целевой и фактической температурой), её интеграл (накопленную ошибку) и производную (скорость изменения), сглаживает регулирование. Меньше скачков, точнее температура, меньше расход энергии.Example: PID control (proportional–integral–derivative) in home heating — measures the error (the difference between the target and actual temperature), its integral (accumulated error) and its derivative (rate of change), and smooths the regulation. Fewer swings, a more accurate temperature and lower energy use.

🇬🇧 English summary (click to expand)

A control system regulates physical behaviour using the IPO model plus optional feedback. Open-loop systems (a timer-driven toaster) follow a fixed sequence regardless of result; closed-loop systems (thermostats, cruise control) feed measured output back to the controller so the input can be corrected in real time. The key components are the controller (often a microcontroller or PLC), sensors that convert temperature, light or pressure into electrical signals, actuators such as motors, valves and heaters that drive physical change, transducers that switch one energy form for another, and the control algorithm — frequently a PID loop — that decides the output.

Можешь назвать любые 4–6 — этого достаточно для большинства вопросов.Ten OS functions: memory, files, devices, network, UI, security, processes, power, peripherals, scheduling. You can name any 4–6 of them — that is enough for most questions.
  • Процесс ≠ программа: программа — пассивный код, процесс — активное выполнение.Process ≠ program: a program is passive code; a process is active execution.
  • Планирование: FCFS (просто), round robin (справедливо), multilevel (смешано), priority (real-time). На экзамене различай по двум осям — fairness vs efficiency и pre-emptive vs non-pre-emptive.Scheduling: FCFS (simple), round robin (fair), multilevel (mixed), priority (real-time). In the exam, distinguish them along two axes — fairness vs efficiency and pre-emptive vs non-pre-emptive.
  • Polling vs Interrupts: interrupts для частых, непредсказуемых, low-latency и batteries; polling для редких, регулярных, mains.Polling vs interrupts: interrupts for frequent, unpredictable, low-latency events and battery-powered devices; polling for rare, regular events and mains-powered devices.
  • HL — многозадачность: ОС жонглирует процессами через context switching. Главные риски — deadlock, starvation, thrashing; на каждое есть стратегия (detection/avoidance, ageing, оптимизация памяти).HL — multitasking: the OS juggles processes through context switching. The main risks are deadlock, starvation and thrashing; each has a strategy (detection/avoidance, ageing, memory optimisation).
  • HL — управляющая система: IPO + feedback. Open-loop — без обратной связи (тостер на таймере), closed-loop — с обратной связью (термостат, круиз-контроль).HL — control system: IPO + feedback. Open-loop — no feedback (a toaster on a timer), closed-loop — with feedback (a thermostat, cruise control).
  • HL — пять компонентов: controller, sensors, actuators, transducer, control algorithm. Запомни конкретные примеры: PLC, thermocouple, solenoid valve, piezoelectric sensor, PID.HL — five components: controller, sensors, actuators, transducer, control algorithm. Remember the specific examples: PLC, thermocouple, solenoid valve, piezoelectric sensor, PID.
  • HL — реальные применения: 8 канонических примеров — авто-машины, термостаты, лифты, стиралки, светофоры, полив, охрана, двери. Для каждого знай датчик → контроллер → актуатор.HL — real-world applications: 8 standard examples — cars, thermostats, elevators, washing machines, traffic signals, irrigation, security, doors. For each one, know the sensor → controller → actuator chain.
  • На экзамене часто спрашивают «сравни X и Y» — отвечай через таблицу: fairness, efficiency, pre-emption, use case для планирования; event frequency, CPU overhead, power, latency, security для polling vs interrupts.In the exam you are often asked “compare X and Y” — answer in a table: fairness, efficiency, pre-emption, use case for scheduling; event frequency, CPU overhead, power, latency, security for polling vs interrupts.
